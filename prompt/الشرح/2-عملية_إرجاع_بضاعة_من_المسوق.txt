================================================================================
                    عملية: إرجاع بضاعة من المسوق إلى المخزن
================================================================================

📋 نظرة عامة:
--------------
عملية إرجاع المسوق للبضاعة إلى المخزن الرئيسي تمر بعدة مراحل من الإنشاء حتى التوثيق النهائي.
البضاعة المرجعة تعود من مخزون المسوق الفعلي إلى المخزن الرئيسي.

================================================================================
                        المراحل والجداول المتأثرة
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│ المرحلة 1: إنشاء طلب الإرجاع (Pending)                                     │
└─────────────────────────────────────────────────────────────────────────────┘

🔹 الفاعل: المسوق (Salesman/Marketer)
🔹 الشرط: يجب أن تكون البضاعة موجودة في marketer_actual_stock

📊 الجداول المتأثرة:
--------------------

1️⃣ marketer_return_requests
   - يتم إنشاء سجل جديد
   - الحقول المستخدمة:
     • id (تلقائي)
     • invoice_number (رقم فاتورة الإرجاع)
     • marketer_id (FK → users.id) - معرف المسوق
     • keeper_id (FK → users.id) - أمين المخزن المستلم
     • approved_by (NULL في البداية)
     • documented_by (NULL في البداية)
     • status = 'pending'
     • stamped_image (NULL في البداية)
     • created_at (وقت الإنشاء)
     • updated_at

2️⃣ marketer_return_items
   - يتم إضافة سجل لكل منتج في الإرجاع
   - الحقول المستخدمة:
     • id (تلقائي)
     • return_request_id (FK → marketer_return_requests.id)
     • product_id (FK → products.id)
     • quantity (الكمية المرجعة)

📌 ملاحظة: في هذه المرحلة لا يتأثر أي مخزون


┌─────────────────────────────────────────────────────────────────────────────┐
│ المرحلة 2: موافقة أمين المخزن (Approved)                                   │
└─────────────────────────────────────────────────────────────────────────────┘

🔹 الفاعل: أمين المخزن (Warehouse Keeper)
🔹 الشرط: التحقق من أن الكمية موجودة في مخزون المسوق الفعلي

📊 الجداول المتأثرة:
--------------------

1️⃣ marketer_return_requests
   - تحديث السجل الموجود
   - الحقول المحدثة:
     • approved_by (FK → users.id) - معرف أمين المخزن الموافق
     • status = 'approved'
     • updated_at (وقت الموافقة)

📌 ملاحظة: في هذه المرحلة لا يتأثر أي مخزون، فقط الموافقة المبدئية


┌─────────────────────────────────────────────────────────────────────────────┐
│ المرحلة 3: رفض أمين المخزن (Rejected) - احتمال بديل                        │
└─────────────────────────────────────────────────────────────────────────────┘

🔹 الفاعل: أمين المخزن (Warehouse Keeper)
🔹 السبب: قد يكون بسبب تلف البضاعة أو عدم مطابقتها للمواصفات

📊 الجداول المتأثرة:
--------------------

1️⃣ marketer_return_requests
   - تحديث السجل الموجود
   - الحقول المحدثة:
     • approved_by (FK → users.id) - معرف أمين المخزن الرافض
     • status = 'rejected'
     • updated_at

📌 ملاحظة: لا يتأثر أي مخزون في حالة الرفض، البضاعة تبقى مع المسوق


┌─────────────────────────────────────────────────────────────────────────────┐
│ المرحلة 4: إلغاء المسوق (Cancelled) - احتمال بديل                          │
└─────────────────────────────────────────────────────────────────────────────┘

🔹 الفاعل: المسوق (Salesman/Marketer)
🔹 الشرط: يمكن الإلغاء فقط إذا كانت الحالة 'pending'

📊 الجداول المتأثرة:
--------------------

1️⃣ marketer_return_requests
   - تحديث السجل الموجود
   - الحقول المحدثة:
     • status = 'cancelled'
     • updated_at

📌 ملاحظة: لا يتأثر المخزون لأن الإلغاء يحدث قبل الموافقة


┌─────────────────────────────────────────────────────────────────────────────┐
│ المرحلة 5: التوثيق النهائي (Documented)                                    │
└─────────────────────────────────────────────────────────────────────────────┘

🔹 الفاعل: أمين المخزن (Warehouse Keeper)
🔹 الشرط: يجب أن تكون الحالة 'approved'

📊 الجداول المتأثرة:
--------------------

1️⃣ marketer_return_requests
   - تحديث السجل الموجود
   - الحقول المحدثة:
     • documented_by (FK → users.id) - معرف أمين المخزن الموثق
     • stamped_image (صورة الفاتورة المختومة)
     • status = 'documented'
     • updated_at (وقت التوثيق)

2️⃣ marketer_actual_stock
   - خصم الكميات من المخزون الفعلي للمسوق
   - الحقول المحدثة:
     • quantity = quantity - الكمية_المرجعة (لكل منتج)

3️⃣ main_stock
   - إضافة الكميات إلى المخزن الرئيسي
   - الحقول المحدثة:
     • quantity = quantity + الكمية_المرجعة (لكل منتج)
     • updated_at (وقت التحديث)

4️⃣ warehouse_stock_logs
   - تسجيل حركة المخزن
   - الحقول المستخدمة:
     • id (تلقائي)
     • invoice_type = 'sales_return'
     • invoice_id (معرف طلب الإرجاع)
     • keeper_id (FK → users.id)
     • action = 'return'
     • created_at

📌 ملاحظة: الآن فقط تتحرك البضاعة بعد رفع الفاتورة المختومة


================================================================================
                            ملخص الجداول المتأثرة
================================================================================

✅ جداول أساسية (تتأثر في كل الحالات):
   1. marketer_return_requests
   2. marketer_return_items

✅ جداول المخزون (تتأثر عند التوثيق فقط):
   3. marketer_actual_stock (خصم)
   4. main_stock (إضافة)
   5. warehouse_stock_logs

✅ جداول مرجعية (للقراءة فقط):
   - users (للمسوق وأمين المخزن)
   - products (لمعلومات المنتجات)

================================================================================
                            ملاحظات مهمة
================================================================================

⚠️ قواعد العمل:
   1. لا يمكن إرجاع كمية أكبر من الموجودة في marketer_actual_stock
   2. لا يمكن إلغاء طلب الإرجاع بعد الموافقة عليه
   3. يجب رفع صورة الفاتورة المختومة عند التوثيق النهائي
   4. ⚠️ البضاعة لا تتحرك إلا عند التوثيق (documented) وليس عند الموافقة
   5. البضاعة تنتقل من marketer_actual_stock → main_stock عند التوثيق فقط
   6. لا يوجد مخزون محجوز في عملية الإرجاع

🔐 الصلاحيات:
   - المسوق: إنشاء طلب الإرجاع، الإلغاء (pending فقط)
   - أمين المخزن: الموافقة، الرفض، التوثيق النهائي

📊 التقارير المتاحة:
   - طلبات الإرجاع حسب الحالة
   - حركة المخزون (إرجاعات)
   - مخزون المسوق بعد الإرجاع
   - سجل التوثيقات

🔄 الفرق بين إرجاع المسوق وإرجاع المتجر:
   - إرجاع المسوق: من marketer_actual_stock → main_stock
   - إرجاع المتجر: من store_actual_stock → marketer_actual_stock (ثم تقليل الدين)

💡 حالات الاستخدام:
   - بضاعة زائدة عن حاجة المسوق
   - بضاعة قريبة من انتهاء الصلاحية
   - بضاعة بها عيوب تصنيع
   - إعادة توزيع البضاعة بين المسوقين
